# Frontend reference

Deep implementation reference for `web/`. This is detail beyond what
`CLAUDE.md`'s architecture section needs to state as invariants; consult this
file when working in the frontend. For voice/copy conventions and Playwright
verification procedure, see the `documentation` and `testing` skills
respectively, not this file.

## Overview

`web/src/`, `App.tsx` does simple state-based view switching (`environments` / `environment-edit` / `interview` / `score` / `vulnerabilities`), no router library. `pages/` holds the five screens, `components/` the shared pieces (`SeverityPill`, `AnimatedScore`, `ScoreChanges`, `EnvironmentResultRow`, `ScoreResult`, `NvdVectorPicker`, `Icon`, `Modal`, `ThemeToggle`, `MarkdownContent`, `MoreExpander`, `WarningBanner`, `CveDetailsView`). `api.ts` wraps every `/api/*` call; `types.ts` mirrors the server's response shapes.

- `ScoreResult.tsx` (extracted from what used to be inline in `ScorePage.tsx`) renders the base-score-card + per-environment result list, and optionally an inline-expand "Save" action (`onSave` prop) that POSTs to `/api/vulnerabilities`. Omitting `onSave` hides the control, used when viewing an already-saved item from `SavedVulnerabilitiesPage.tsx`. Its optional `overwriteLabel` prop shows an italic note in the save panel when the save will update an existing entry rather than create one. See "Scoring page" below for the optional `defaultDescription` and `onClear` props.
- `web/src/lib/severity.ts`, `nvdSeverityToAppSeverity(raw, baseScore)` maps NVD's upper-case `baseSeverity` strings (or the score-band fallback when NVD omits one) onto the app's title-case `Severity` union; also reused to score-derive a severity pill for the saved-vulnerabilities list and its severity filter, which don't carry `baseSeverity` at all.

The results screen's signature interaction: each environment's score animates from the base score to its modified score on load (`AnimatedScore`), with color morphing through the severity scale in transit, the "a 10 might actually be a zero" moment, dramatized once. Respects `prefers-reduced-motion`. `None` severity deliberately renders with no color at all (quiet muted text, no pill) rather than a fifth hue, see "Frontend design" in `CLAUDE.md` for why. The severity pill next to the animated number derives its severity from the same live (in-transit) value as the number's color, not the final value, both must land together when the animation settles, or the pill spoils the reveal by snapping to its end state early.

Each changed-metric line in the "why" panel (`ScoreChanges.tsx`) shows a colored ▲/▼/– glyph plus a real signed score number (e.g. `-1.3`, `±0.0`) sourced from the server's `ScoreChange.impact`/`direction` fields, plus a closing "Total:" line and a small order-dependency caveat. Exact per-metric numeric attribution isn't inherently well-defined for CVSS (the formula isn't additive), so `impact` is a **sequential/waterfall** figure: `applyEnvironment()` applies each change one at a time and measures the score movement at each step, which means the per-line numbers always telescope exactly to the row's total delta (reassuring when a user asks "how did three items add up to +1.6?") even though the *split* between two interacting changes could differ if the application order changed. `direction` is simply derived from `impact`'s sign (`worse`/`better`/`neutral`), not a separate ordinal judgment. The "Total:" line gets a `why-total-worse`/`why-total-better` class (bold, `--severity-critical-text`/`--severity-low-text`) derived from the total's sign; zero stays neutral. The severity pill (in both `AnimatedScore` and the base-score-card) sits in a fixed-width `.severity-slot` sized to the longest severity word ("CRITICAL") so score figures stay aligned in a column down a result list regardless of which severity word appears per row; `.pill-none`'s chrome-less rendering still fits the same slot.

`EnvironmentResultRow.tsx`'s collapsed summary renders a red warning-triangle icon immediately before the animated score figure whenever `result.delta > 0`, sized to the score figure's line height (`--text-2xl`) via `.more-vulnerable-icon`, this needs to be announced to screen readers, unlike every other decorative icon use in the app, so `Icon.tsx`'s optional `aria-label` prop flips the SVG from `aria-hidden` to `role="img"` + a `<title>` when set. Its expanded detail panel also renders a `.more-vulnerable-warning` callout (a thin spacing modifier on the shared `.callout-warning` base class, a red-accented card + `Icon name="warning"`, backed by a `--warning-wash` token, a translucent tint of `--action-red-text`) whenever `result.delta > 0`, stating plainly that the environment is more exposed than the base score suggests. `.callout-warning` is also what backs `WarningBanner.tsx`, used by the Scoring page's CVE-lookup and Major-CVEs-fetch errors, one visual language for "something's wrong, here's why" everywhere in the app. Because both the Scoring-page results and the saved-vulnerability detail view render through the same `EnvironmentResultRow`, one implementation covers the more-vulnerable warning in both places.

## Design system

Lives in `web/src/styles.css` as CSS custom properties (no framework): IBM Plex Mono for headlines/scores/vector strings, Archivo for body copy (via `@fontsource/*`, self-hosted, **never** load fonts from a CDN, the app must work fully offline). Import only the `latin-*.css` subset files from `@fontsource` packages, not the bare weight files, the latter pull in every unicode subset (cyrillic, vietnamese, greek, ...) and roughly quadruple the font payload for no reason in an English-only UI.

- `web/src/lib/markdown.ts`, `renderMarkdown(source)` runs `marked` (GFM, `breaks: true`) then sanitizes the output HTML through `dompurify` (an `afterSanitizeAttributes` hook forces `target="_blank"`/`rel="noopener noreferrer"` on every link; `<style>` is additionally forbidden). This is the only place raw description text becomes HTML, descriptions are stored as-is server-side (plain `TEXT` columns, no server-side sanitization) and sanitized only at render time, so raw markdown source round-trips intact through edit forms. `MarkdownContent.tsx` wraps it in a `<div className="markdown">` via `dangerouslySetInnerHTML`, the only `dangerouslySetInnerHTML` call in the app, safe specifically because it always goes through the sanitizer first. Wired up in `EnvironmentsPage.tsx`'s list rows, `EnvironmentEditPage.tsx`'s detail view (edited as a plain `.textarea`, never a WYSIWYG editor, consistent with the rest of the app's plain-CSS design), and the Saved-vulnerabilities list. `web/src/lib/markdown.test.ts` is the mandated safety test (Vitest + `jsdom`, see `web/vitest.config.ts`), covers basic formatting, forced link attributes, and stripping of `<script>`, inline event-handler attributes, `javascript:` URIs, and `<style>`.
- `Icon.tsx`, a single component (`name` prop) rendering bundled inline SVGs (`trash`, `pencil`, `sun`, `moon`, `chevron`, `question`, `warning`, `external-link`, `eye`, `eye-off`), no icon font/CDN. Icon-only buttons always carry `aria-label`.
- Semantic action colors are tokens in `styles.css`, deliberately distinct hues from the severity palette (which stays reserved, never reused for non-data purposes): `--action-green`/`--action-yellow` (solid fills, near-black `--action-ink` text on top) and `--action-red-text` (theme-varying outline/icon color, same pattern as `--severity-*-text`). Contrast-validated in both themes via the dataviz skill's `validate_palette.js` `contrast()` export against the real `--surface`/`--surface-card` values, e.g. `--action-green` clears 4.76:1 (light) / 8.36:1 (dark) with black text, `--action-red-text` clears 5.03:1 (light) / 5.83:1 (dark). `--accent` itself clears 4.5:1+ as border/text against both surfaces in both themes (6.32-6.75:1).
- Button classes: `.button`/`.badge` use an accent-outline pattern (`--accent` border + text, transparent background, `--accent-wash` hover fill for `.button`). `.button-primary` uses theme-inversion tokens (`--button-contrast-bg`/`--button-contrast-ink`, theme-scoped) rather than a flat `--accent` fill. `.button-save` (solid green, "Save", never an icon) and `.button-cancel` (solid yellow, "Cancel", never an icon) share `.button`'s size system. `.button-quiet`, `.link-button`, and `.icon-button-quiet` deliberately stay neutral, semantic colors are reserved for Save/Cancel/Delete/primary actions, not a general recolor. `.icon-button` is a fixed-size (2.25rem) square icon-only control; `.icon-button-delete` (red outline + `Icon name="trash"`) and `.icon-button-edit` (accent outline + `Icon name="pencil"`, same box model as delete just in the `--accent` family, an earlier solid-yellow treatment read as a glaring square dominating every row, so it moved to this quieter outline) are its semantic variants.
- Active tabs (`.tab.is-active`) render a solid `--accent` fill + `--accent-ink` text in both themes (a deliberate exception to `.button-primary`'s theme-inversion rule, scoped to tabs specifically). **Gotcha**: `.tab:hover:not(:disabled)` (specificity 0,3,0) must be scoped to `:not(.is-active)`, or it beats `.tab.is-active` (0,2,0) and silently flips the active tab's hover text to the same color as its background (invisible), caught via Playwright + `getComputedStyle`, not visually (a static screenshot of the non-hovered state looked fine); a hover-state screenshot or computed-style check is needed to catch this class of bug, a plain screenshot isn't enough.
- `Modal.tsx` exports `Modal` (generic dialog: blurred backdrop via `backdrop-filter`, `role="dialog"`/`aria-modal`, focus-trapped, closes on Escape or backdrop click, restores focus to the trigger on close, takes an optional `className`) and `ConfirmModal` (the delete-confirmation specialization, yellow Cancel / red-outline-text "Delete"). Neither list page uses `window.confirm()`.
- Theming: `web/src/lib/theme.ts` reads/writes `localStorage` (`localscore-theme`) and toggles a `data-theme="light"|"dark"` attribute on `<html>`. `main.tsx` applies the preferred theme (stored value, else `prefers-color-scheme`) *before* the first React render to avoid a flash of the wrong theme. `styles.css` defines dark tokens three times by design, behind `@media (prefers-color-scheme: dark)` (pre-JS default), and behind `:root[data-theme="dark"]`/`:root[data-theme="light"]` (both higher-specificity than a bare `:root`, so the in-app toggle always wins over system preference), keep all three in sync when editing dark-mode tokens. `ThemeToggle.tsx` renders a real `<button role="switch" aria-checked>` (`.theme-switch`), a pill track with a sliding thumb, light = off (thumb left, neutral `--surface-sunken` track), dark = on (thumb right, `--accent`-filled track), sitting at the far right of the header (`.nav` has `margin-right: auto` to push it there); the active icon rides inside the thumb at 18px and shows the icon for the *action* (moon while light, sun while dark), not the current state.
- `html { overflow-y: scroll; }` reserves scrollbar space unconditionally, so navigating between a short page (e.g. an empty Saved list) and a long one no longer shifts centered content horizontally.
- Severity pill ink is theme-scoped (`--severity-ink`: `#ffffff` light, `#0b0b0b` dark) with the fill hues (`--severity-low/medium/high/critical`) deepened per-theme to keep white text readable on the light-theme fills (each cleared to ≥4.5:1 against white via the dataviz `contrast()` procedure). Foreground *text* uses the separate `--severity-*-text` tokens, not the raw fill hues, wherever severity color appears as text-on-surface rather than fill-with-text-on-top (`AnimatedScore.tsx`'s score-number color, `ScoreChanges.tsx`'s deltas, the outline `SeverityPill` variant), the fill and text-on-surface contrast pairings are different (e.g. `--severity-medium` measures only ~1.8:1 as raw text against the light surface), and the fill tokens were only ever validated for fill-with-near-black-text.
- `SeverityPill` takes an optional `variant?: "solid" | "outline"` (default `"solid"`); the Saved-vulnerabilities list and the filter-chip severity legend use `"outline"` (border + text colored by severity, transparent fill) since a solid pill there would carry the same visual weight as neighboring neutral `.badge` tags.
- `.badge`/`.badge-severity` share one box model (shape/size/weight), differing only in color. The "ready" badge (`.badge.is-complete`) uses the outline tag pattern with a dedicated `--action-green-text` token, kept separate from the reserved severity palette.
- `QuestionHelpModal.tsx` (interview question help): a circled `?` `icon-button-quiet` next to the question title opens the shared `Modal` with `whyWeAsk` → `helpDetail` (2-4 sentences per question) → `finePrint`, in that order. `Modal`'s `modal-fixed-height` class gives `.modal-body` a `min-height` sized to the largest of the 12 questions' content so the dialog doesn't visibly resize between questions; `.modal-header h2` uses the body font/weight 700 (scoped to modals only, page headings elsewhere keep IBM Plex Mono). `helpOpen` state resets on question change so switching questions via the progress ticks doesn't leave a stale modal open for the wrong question.

## Environments page

- `EnvironmentsPage.tsx`'s page description targets a non-technical reader and includes a `MoreExpander` (a thin `<details>`/`<summary>` wrapper, also reused for the Scoring page's "More") explaining the base-score-vs-environmental-metrics distinction. The create form collects name, an optional description (`.textarea`), and an optional `location` (`.input`); `.new-environment-form` has `gap: var(--space-5)` so fields don't touch.
- `EnvironmentEditPage.tsx` is the dedicated edit view: rename (`.input`), description (`.textarea`, markdown-rendered elsewhere), location (`.input`), a red-outline trash `icon-button-delete` (guarded by `ConfirmModal`), and green `.button-save`/yellow `.button-cancel` calling `updateEnvironment()` (`api.ts`) against `PUT /api/environments/:id`. A second card surfaces "Answer interview" / "Re-answer interview" (labeled by `interviewCompletion["3.1"]`) to reach the wizard, plus one `.vector-string`-styled line per CVSS version present in `environment.metrics` (e.g. `CVSS 3.1: MAV:A/MAC:H/CR:L/IR:M/AR:L`) rendered below the status paragraph. `formatProfile()` joins `METRIC:VALUE` pairs in a canonical order (`MAV, MAC, MAT, MPR, MUI, MVC/MC, MVI/MI, MVA/MA, MSC, MSI, MSA/MS, CR, IR, AR`, then v4 supplemental `S, R, V, RE`) covering both the v4.0 and v3.1 metric names the catalog emits, falling back to insertion order for anything unanticipated; an environment with no answers (`metrics: []`) shows no profile line at all.
- `EnvironmentsPage.tsx`'s list-row action: once `interviewCompletion["3.1"]` is true the row shows the accent-outline pencil `icon-button-edit`; until then it shows a text "Answer interview" button. Both open `EnvironmentEditPage`, never the interview wizard directly (the Create form's "Create & start interview" still jumps straight into the wizard on creation, since there's nothing to edit yet).
- **`.environment-row` layout**: `flex-wrap: nowrap` at desktop (with `align-items: flex-end` so the action cluster anchors to the row's bottom-right) and `overflow-wrap: anywhere` on `.environment-name`, mirroring the Saved page's `.vulnerability-row-header` fix for the same bug: an unwrapped `flex-wrap: wrap` let a long markdown description push the edit/delete action cluster onto its own line below the card content. A `@media (max-width: 480px)` override restores `flex-wrap: wrap` for a deliberate stacked mobile layout.
- `InterviewPage.tsx` has no "Save & exit" control, a plain `.link-button` "← Back to environment" sits above the `<h1>` instead; answers still auto-save per-answer. `App.tsx` routes the interview's `onDone` (both the back-link and the final "Done" button) back to `EnvironmentEditPage` for that environment, not the full environments list.
- **Location field**: migration `0004_environments_location.sql` adds `environments.location TEXT NOT NULL DEFAULT ''`, a short, optional, single-line, plain-text place label ("us-east-1", "Building 4, rack 12"), deliberately not markdown and not involved in scoring/derivation/the interview. `POST`/`PUT /api/environments` accept an optional `location` (COALESCE-on-missing-field pattern), trimmed server-side; a non-empty location renders as a small muted `.environment-location` line directly under the environment name, above the markdown description.
- **Quote stripping**: `server/src/lib/strings.ts`'s `stripWrappingQuotes()` removes one matched pair of wrapping quotes (straight or curly, double or single) after trimming, repeating until no wrapping pair remains, so `"'My Lab'"` fully unwraps to `My Lab`. Applied to `name` and `location` on both `POST /api/environments` and `PUT /api/environments/:id` (not `description`, markdown legitimately uses quotes). A name that becomes empty after stripping still 400s. The create/edit forms' placeholders don't model quoted examples (`e.g. My Data Center`, not `e.g. "My Data Center"`) since that's what taught users to type them in the first place; the server-side strip is the backstop for API callers and anyone who quotes anyway.
- **Two-tier risk-warning system**: an environment can be flagged two independent ways, both surfaced as a red `Icon name="warning"` in the row's badge row on `EnvironmentsPage.tsx` (not itself interactive, Edit is the path to the explanation) and explained in a `.callout-warning` on `EnvironmentEditPage.tsx`.
  - **Tier 1, `raisesScores`** (`server/src/scoring/raising.ts`): a per-CVSS-version boolean computed from metric+value pairs (not question IDs, so catalog evolution keeps working). Current trigger set: `4.0` flags `MSC/MSI/MSA = H` (Q8 stepping-stone) and `MSI`/`MSA` = `S` (Q9 safety=yes); `3.1` flags `MS = C` (Q8). Only `override` effects are ever checked (`cap` never raises severity by definition). An earlier version of this rule also flagged `CR/IR/AR = H` (Q5/Q6/Q7 "Catastrophic"), but that over-triggered, an environment that legitimately has a lot to lose (e.g. a government IL6 system) was flagged permanently, making the flag meaningless exactly where stakes are highest, so `CR`/`IR`/`AR` were dropped from the trigger set. `computeRaisesScores()` returns the per-version booleans; `computeRaisingAnswers()` returns deduplicated `{ questionId, optionId }` provenance.
  - **Tier 2, `redFlags`** (`server/src/scoring/redflags.ts`): computed straight from `environment_answers` (not derived metrics, since Q10-Q12's supplemental answers never produce a metric), deliberately catalog-coupled (conditions reference `questionId`/`optionId` pairs directly, defended by a catalog-integrity test asserting every referenced answer, exported as `REFERENCED_ANSWERS`, exists in the shipped catalog). "High stakes" = any of Q5/Q6/Q7 "Catastrophic" or Q9 safety "yes"; every rule pairs a stakes condition with a readiness gap so a flag never fires on stakes alone: `uncertain_recovery` (high stakes + Q10 "Uncertain"), `concentrated_availability` (Q7 "immediate" + Q11 "concentrated"), `hard_to_patch` (high stakes + Q12 "Hard"), `exposed_high_stakes` (Q1 "Directly from the internet" + Q2 "Nothing beyond the basics" + high stakes), `open_access_high_stakes` (Q3 "Anyone: no login needed" + high stakes, suppressed when Q1 is "No network path at all", an air-gapped console with no login isn't the same risk as an internet-reachable one, since there's no path to that open login for an outsider). Skipped/unanswered questions never satisfy a condition. Two candidates from the same audit were explicitly rejected and are documented inline in `redflags.ts`: "interactive human use + safety-critical" (interactivity is an attack-surface fact, not a readiness gap, so pairing it with safety stakes would flag properly-secured staffed sites for no operational reason) and "concentrated value density + uncertain recovery" (value density is a display-only v4 supplemental signal, not one of the `HIGH_STAKES_ANSWERS` magnitudes, so it risked the same CR/IR/AR-always-H over-triggering that Tier 1 hit and dropped).
  - `GET /api/environments` (list) returns `raisesScores: { "4.0": boolean, "3.1": boolean }` and `redFlags: string[]` (ids). `GET /api/environments/:id` (detail) additionally returns `raisingAnswers` and `redFlags: { id, answers[] }[]`, using the same deduplicated-provenance shape. Both are computed at request time from `environment_answers` rather than the persisted `environment_metrics` cache, since only the live derivation carries questionId/optionId provenance. An environment with no answers reports `false`/`false` and empty arrays.
  - `EnvironmentEditPage.tsx` fetches the catalog to translate provenance into plain English and renders up to two `.callout-section` blocks (score-raising, then red flags) inside the `.callout-warning`, separated by a hairline divider only when both are present; either renders alone when only one tier triggers, and the callout disappears entirely when neither does. Each red flag renders its plain-English meaning (`RED_FLAG_COPY`) followed by its responsible question/answer pairs.
  - **Callout readability**: each `.callout-section`'s title/explanatory paragraph is grouped in its own `.callout-section-intro` div, visually distinct from the indented (`padding-left: var(--space-4)`) `.raises-scores-list` that follows. Each list item renders as two lines: a bold `Q:` prefix + question text, then a normal-weight `A:` prefix + answer text, a scoped `.raises-scores-list li p + p { margin-top: 0; }` override keeps that pair tight while the general `.callout-section p + p` rule gives wider spacing (`var(--space-3)`) between successive pairs, and an even wider gap (`var(--space-5)`) separates each section/red-flag block's own intro. Both the score-raising section and every red-flag block share the one `.raises-scores-list` class.
  - **Collapsed-by-default disclosure**: the two-tier callout is a real `<button aria-expanded>` (`.callout-disclosure-summary`, same interaction pattern as `CveDetailsView.tsx`'s `.cve-details-summary`), collapsed by default, showing a single one-line plain-English summary (varying by which tier(s) triggered) with the red-accented warning styling and a rotating chevron; clicking reveals the existing two-tier `.callout-section` content unchanged inside `.callout-disclosure-body`. Both tiers live inside the one disclosure. This keeps a multi-answer-provenance callout from pushing the name/description form down the page. The environments list page's warning icon is unaffected by this, Edit remains the path to the explanation.

## Saved vulnerabilities page

- `SavedVulnerabilitiesPage.tsx` mirrors `EnvironmentsPage.tsx`'s list/empty-state/delete structure, with inline expand-to-view-and-rescore per row via `ScoreResult`. Each `<li>` is one `.card.vulnerability-row` containing both the clickable header and the conditionally-rendered detail panel (reuses `.result-row-detail`'s divider treatment), not a header card with a separate unstyled sibling, so the expanded content stays visibly bounded within its own card. Clicking anywhere on the header toggles expand/collapse; the View/Hide, Edit, and Delete buttons inside it call `event.stopPropagation()` so they don't also re-trigger the row's own toggle. `vulnerabilities.description` renders via `MarkdownContent`, same as the environments list.
- The accent-outline pencil `icon-button-edit` per row (next to View/Delete) swaps the row's header for an inline edit form (`.environment-edit-form`, wrapped in `.vulnerability-row-edit` to restore the `var(--space-5)` padding that the view-mode layout otherwise sets to `0`) with label/description fields and green `.button-save`/yellow `.button-cancel`, calling `updateVulnerability()`. No separate edit page, the row itself becomes the form, then reverts to the normal header on save/cancel.
- The View/Hide button is a neutral 2.25rem `.icon-button-quiet` with `eye`/`eye-off` icons (view/hide isn't one of the reserved semantic actions), and stays in place (no "Loading..." label swap) while the detail fetch is in flight.
- `.vulnerability-row-header .environment-name` gets `overflow-wrap: anywhere` so a pasted-vector save's default vector-string label (150+ chars, unbroken) wraps inside the card instead of overflowing; `.environment-row-main` has `min-width: 0`. The badge for a pasted-vector save reads "Vector" (not "Pasted vector"), kept short to match "NVD".
- **Action cluster** (`.environment-row-actions`, the eye/edit/delete cluster): `.vulnerability-row-header` uses `align-items: flex-end` + `flex-wrap: nowrap` at desktop, so the cluster anchors to the header's bottom-right and tracks the bottom edge of however tall the text column gets; a `@media (max-width: 480px)` override restores `flex-wrap: wrap` for a deliberate stacked layout at that width. `.environment-row-actions` keeps `flex-shrink: 0`.
- **CVE details disclosure** (`CveDetailsView.tsx`, shared with the Scoring page, see below): `.cve-details-summary` is its own bounded row (`border` + `border-radius: var(--radius-md)` + `background: var(--surface-sunken)`, darkening to `--surface-card` on hover) with a rotating chevron (`size={20}`), collapsed by default, expanding on click to reveal description/dates/affected-products/references. Inside the expanded body, affected-product chips and reference tags are recolored to `--ink-secondary` (not the app's usual accent-outline `.badge`, and not `--ink-muted`, which fails contrast at this size) so the hierarchy reads link = accent = interactive, chip = neutral = metadata. A plain external NVD link (`Icon name="external-link"`, `target="_blank" rel="noopener noreferrer"`) renders in a `.cve-details-footer` (`display: flex; justify-content: flex-end`) as the body's last element when `cveId` is present, inside the expanded body rather than the summary button, so it needs no `stopPropagation` (nesting an `<a>` inside the summary `<button>` would be invalid HTML/ARIA). `CveDetailsView` takes an optional `showDescription` prop (default `true`, so the Scoring page's fresh-lookup flow is unaffected). The Saved page passes `showDescription={!vuln.description}` for its expanded row, since an NVD-sourced saved row already shows its own `description` field in the row header, avoids showing the NVD description twice, while still surfacing it inside the details disclosure if the user has cleared the row's own description.
- **Filter/search control bar** (`.filter-bar`, between the page header and the list): Type (`All`/`NVD`/`Vector`, single-select) and Severity (`All`/`Critical`/`High`/`Medium`/`Low`, multi-select) chip groups, plus a debounced (280ms) search `.input` that spans the full row width (its own row via `flex-basis: 100%`, not shrink-wrapped). Filter options are a `.filter-chip` pill control sharing the app's accent-outline-to-solid-accent-fill "selected" convention (same pattern as `.tab.is-active`/`.badge.is-complete`) rather than reusing `.tabs` (reserved for page-level mode switching) or a plain `.badge`. Severity chips double as a color legend, using the same `--severity-*-text` (outline, unselected) and `--severity-*`/`--severity-ink` (solid fill, selected) tokens validated elsewhere, a deliberate, narrow reuse of the severity palette for an actual severity control.
  - **Type** stays single-select (`TypeFilter` string state), since its options are mutually exclusive by construction. **Severity** is a `Set<SeverityFilter>` (`severitySet`): clicking a severity chip toggles membership, multiple can be active at once, and "All" represents the empty set (clicking it clears the set; there is deliberately no way to distinguish "all four selected" from "All" in the UI). Filtering passes when the set is empty or the row's severity is a member. Both are client-side `useMemo` filters over the already-fetched list. Severity matching reuses `nvdSeverityToAppSeverity("", vuln.baseScore)`, the exact function the row's own `SeverityPill` calls, so a row can never filter into a bucket different from what it visibly shows; `None`-scored rows (a 0.0) have no severity chip and only appear when the set is empty.
  - **Search** is server-side (`GET /api/vulnerabilities?q=`, see `docs/BACKEND.md`). `listVulnerabilities()` (`web/src/api.ts`) takes an optional `q`; the page debounces `searchInput` into a `searchQuery` state that drives the fetch. Existing no-arg callers (`ScorePage.tsx`'s overwrite-detection fetch) are untouched.
  - Two distinct empty states: "No saved vulnerabilities yet" only when the list is truly empty *and* no filter/search is active; "No saved vulnerabilities match these filters" (with a "Clear filters" `.link-button`) whenever a filter or search is active and yields zero results. A viewed/expanded row that stops matching simply isn't rendered by the filtered map, sufficient to "collapse" it, no separate state reset needed.

## Scoring page

- `ScorePage.tsx` is built around three real tabs (`role="tablist"`/`tab`/`tabpanel`, `.tabs-shell`/`.tabs`/`.tab`) in order: **Look up a CVE** (default), **Paste a Vector**, **Major CVEs**. Each panel opens with a `.tab-purpose` line stating what that tab is for. The page description targets a non-technical reader and has a `MoreExpander` with plain external links to NVD's and MITRE's CVE search (no network call from the app itself, just `<a href>`s).
- **Offline detection**: `web/src/lib/online.ts`'s `useOnlineStatus()` hook wraps `navigator.onLine` plus `online`/`offline` window event listeners, returning a setter too, a CVE lookup that fails with a `502` (NVD unreachable) also flips it false, since `navigator.onLine` is unreliable on some platforms/only reflects the network interface, not actual internet reachability. The "Look up a CVE" tab gets `disabled` + an explanatory tooltip whenever offline; "Major CVEs" gets the same treatment only when it *also* has no cached data to fall back on (checked client-side against the already-fetched `MajorCvesResponse`). An effect auto-switches away from either tab to "Paste a Vector" if the user goes offline while on them.
- **CVE lookup errors**: `WarningBanner.tsx` renders any `cveError` as a red-accented `.callout-warning` card with a warning icon instead of bare error text. Only a `502` (unreachable) redirects to the paste tab, a `404` (not found) or `422` (no CVSS data) stays on the CVE tab with the banner explaining why, since those aren't connectivity problems. Both this banner and the Major CVEs tab's fetch-error banner span the full panel width (`.tab-panel .callout-warning { width: 100%; }`, the root cause was `.score-form`'s `align-items: flex-start` shrink-wrapping children to their text width).
- **Major CVEs tab**: fetched via `getMajorCves()` on mount and rendered as a plain list (`.major-cve-row`) of ID (`--text-lg`, so it reads as the row's primary identifier) + outline `SeverityPill` + score + published date, only the ID and score figure stay mono, the date/prose use the body font. A `"Last updated <timestamp>"` / `"Updated just now"` line reflects the response's `cached`/`fetchedAt`. Clicking a row calls the same `performCveLookup()` used by manual CVE-ID entry and switches to the CVE tab. Each row also renders a plain external NVD link with its own `stopPropagation` (split into a `<button className="major-cve-row-lookup">` plus a sibling `<a>`, since nested interactive elements aren't valid HTML/ARIA).
- **Overwrite messaging**: `ScorePage.tsx` fetches `listVulnerabilities()` on mount (refreshed again after every successful save) and locally matches the current result against that list, by `cveId` for a CVE-sourced lookup, by `result.base.vector` for a pasted vector, to compute an `overwriteLabel` passed into `ScoreResult`'s save panel. This has to be known *before* the save call resolves (the server's `overwritten` response flag alone is too late), so it's derived from client-side state that mirrors what the upsert will match against.
- **Save-time description**: `ScoreResult.tsx`'s save panel has a description `.textarea` below the label input ("Markdown supported" copy, matching the Saved-page edit form); `onSave`'s signature carries a second `description` argument. `SavedVulnerabilitiesPage.tsx` doesn't pass `onSave` to `ScoreResult`, so it's unaffected. `ScoreResult` also takes an optional `defaultDescription` prop (mirroring `defaultSaveLabel`) to prefill the textarea; `ScorePage.tsx` passes the NVD description (`cveLookup.details.description`) only when the result is CVE-sourced (`lookupSource` is set), leaving a pasted-vector result's textarea empty since there's no NVD description behind it. Known asymmetry, documented inline rather than fixed: if a user clears this prefill and saves, the server's existing "prefill only when empty" rule (see `docs/BACKEND.md`) will re-add the NVD description to the stored row on a fresh save. The save panel's input/textarea span the full card width (`.save-form` carries no width clamp); only the field widths changed, the shared Save/Cancel buttons (also used by the Saved page's inline edit form) keep their natural width.
- **Clear-result control**: `ScoreResult` takes an optional `onClear` prop; when present, a red-outline `icon-button-delete` trash button (`aria-label="Clear this result"`) renders at the far right of the save-panel's collapsed row, next to the Save button/Saved confirmation (hidden while the save form itself is open). `ScorePage.tsx` wires it to clear `result`, `lookupSource`, and `error` only, leaving the CVE lookup data and vector textarea untouched so re-scoring works immediately. No confirmation dialog, since clearing is non-destructive (the result can be recomputed). `SavedVulnerabilitiesPage.tsx` doesn't pass `onClear`, so its expanded row shows no clear control (the existing view/hide toggle already serves that purpose there).
- **Stale-result invariant**: a rendered result is only valid for the exact input that produced it. `ScorePage.tsx` clears `result` (and `lookupSource`) at the top of `performCveLookup()` (covers the lookup form, a Major-CVE row click, and Refresh alike, including a same-CVE refresh since NVD data can change between fetches), in the vector textarea's `onChange`, and in the NVD vector picker's `onSelect`. Each clearing site carries a comment noting this is an invariant, not a one-off patch, so a future input source inherits it deliberately. Failed scoring already clears the result.
- **Focus symmetry**: one effect keyed on `mode` focuses `cveInputRef` (`#cve-input`) when `mode === "cve"` (including on the initial render, since "Look up a CVE" is the default tab) and `vectorInputRef` when `mode === "paste"`. The Major CVEs tab has no input. The offline-redirect effect still runs first when applicable, so the focus effect only ever tries to focus a tab that's actually showing.
- **CVE details**: `CveDetailsView.tsx` is the one shared rendering component for both this page's fresh-lookup flow and the Saved page's expanded-row detail view (see `docs/BACKEND.md` for `extractCveDetails()`). The description has no length clamp, the collapsed-by-default disclosure (see "Saved vulnerabilities page" above) is what bounds the page now, not an inner "Show More" toggle.
- **`.option-list` spacing**: the shared `.option-list` class (rendered by both `InterviewPage.tsx`'s question card and `NvdVectorPicker.tsx`) carries no top margin of its own; `.interview-question .option-list` scopes the `var(--space-5)` top margin to the interview specifically. `NvdVectorPicker`'s other two homes (this page's CVE-lookup result and the Saved page's expanded-row detail) already space their own children via a flex `gap` (`.cve-lookup-result`'s `var(--space-4)`, `.result-row-detail.stack`'s `var(--space-5)`), so the shared class doubling that spacing was the bug; each context now owns its own spacing directly.
- The signature score-reveal animation, the "why" panel's waterfall attribution, and the more-vulnerable warning are documented once, up front in "Overview" above, since `ScoreResult`/`EnvironmentResultRow` are shared with the Saved page.
